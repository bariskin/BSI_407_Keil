# 🧭 Шпаргалка по работе с Git Tags

| Действие | Команда | Описание |
|-----------|----------|----------|
| 🏷️ Просмотреть все теги | `git tag` | Показывает список всех тегов |
| 🔍 Посмотреть информацию о теге | `git show v1.0` | Показывает коммит, сообщение и автора тега |
| ➕ Создать аннотированный тег | `git tag -a v1.0 -m "Release v1.0"` | Создаёт тег с описанием (рекомендуется для релизов) |
| ➕ Создать легковесный тег | `git tag v1.0` | Простая метка без описания |
| 🎯 Создать тег для конкретного коммита | `git tag -a v1.0 <commit_hash> -m "Release v1.0"` | Привязывает тег к указанному коммиту |
| 🚀 Отправить один тег на удалённый репозиторий | `git push origin v1.0` | Публикует конкретный тег |
| 🚀 Отправить все теги | `git push origin --tags` | Отправляет все локальные теги на сервер |
| ❌ Удалить локальный тег | `git tag -d v1.0` | Удаляет тег только локально |
| ❌ Удалить тег в удалённом репозитории | `git push origin --delete tag v1.0` | Удаляет тег на сервере |
| 🧾 Проверить теги на сервере | `git ls-remote --tags origin` | Показывает все теги, хранящиеся на удалённом репозитории |

---

💡 **Совет:**  
После отправки тега (`git push origin v1.0`) на GitHub можно сразу создать релиз на странице *Releases* — тег будет использован автоматически.
